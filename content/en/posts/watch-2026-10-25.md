## The essentials

1. A hacker, ChimeraZ, claims campaign-data leaks at three French political parties (LFI, Renaissance, PCF); the figures are unverified.
2. On the vulnerability side, a Collabora Online flaw is being exploited to booby-trap Nextcloud servers, and a Brotli compression flaw forces Node.js, Python and others to patch one by one.
3. HPE fixes eight critical flaws in Aruba Wi-Fi, and Kaspersky shows that an up-to-date PC can remain vulnerable if Secure Boot revocations are not enabled.

### The same hacker claims leaks at LFI, Renaissance and the PCF

**Data breach · Important**

**What happened**
On 24 October, a hacker calling themselves ChimeraZ released for free about 1.27 million rows attributed to La France insoumise (LFI). It is mostly door-to-door canvassing data (addresses, 2026 and 2027 campaigns) and the names or pseudonyms of about 200 activists. On 25 October, ZATAZ reports that the hacker also claims more than 4 million rows at Renaissance and is selling the PCF file. These figures come from the hacker and are unverified; LFI has not confirmed any intrusion.

**Why it matters**
Being linked to a party reveals a political opinion, "sensitive" data more strictly protected by the GDPR (Article 9). The files appear to come from campaign tools (door-to-door apps), not from the party's main system. In GRC, it is a textbook case: side tools and service providers must be part of the risk analysis.

**Key takeaway**
A claim is not proof: we wait for confirmation from the organisation or from the CNIL (the French data protection authority). The volume "in rows" does not say how many people are affected (duplicates, public addresses). With elections approaching, be wary of messages that cite a party and ask for money or credentials.

*Sources: ZATAZ · Cyberattaque.org · Clubic*

### Nextcloud: a Collabora Online flaw exploited to install backdoors

**Vulnerability · Critical**

**What happened**
On 23 October, CISA added CVE-2026-110447 (score 9.2) to its catalogue of exploited flaws. It affects the document server built into Nextcloud ("Built-in CODE Server", the richdocumentscode app) and allows remote command execution. Attackers use it to drop a web shell, then look for passwords and cryptocurrency wallets. The fix (version 26.4.303) has existed since September.

**Why it matters**
Nextcloud and Collabora are widely used in Europe, notably by public administrations and local authorities that want to avoid American clouds. A flaw fixed a month ago but still exploited shows that the real problem is often late patching. US federal agencies have until 26 October to fix it.

**Key takeaway**
If you run a Nextcloud, update the built-in CODE server or uninstall it. Then look for unknown PHP files on the server: patching does not remove a web shell that is already installed. CISA's KEV catalogue is a good list for knowing what to fix first.

*Sources: The Hacker News · CISA*

### Brotli: a compression flaw affects Node.js, Python, Bun and Envoy

**Vulnerability · Important**

**What happened**
CVE-2026-111497, found by OpenAI's security team, is a memory corruption in Google's Brotli decoder (a web compression format). Booby-trapped compressed data can crash a server, or even execute code on it. Node.js, Bun, Envoy, Istio and the Python packages brotli and brotlicffi have released fixes. No real-world exploitation is reported, and no reliable public exploit exists.

**Why it matters**
The fix had been in Brotli's code since February, but without a release before 21 October: nobody had realised it was a security flaw. Because each piece of software embeds its own copy of the decoder, each must be patched separately. Some dependency scanners (such as Dependabot) may not detect the affected Python packages.

**Key takeaway**
A single library can hide in dozens of programs: you need an inventory of your components (SBOM). After updating, restart services and rebuild container images. Check Python brotli versions by hand (1.2.1 is fixed).

*Sources: The Hacker News*

### HPE Aruba: eight maximum-rated flaws in Wi-Fi equipment

**Patches · Important**

**What happened**
HPE fixed 72 flaws in ArubaOS (AOS-8 and AOS-10), the operating system of Aruba's Wi-Fi access points, controllers and gateways. Eight have the maximum score: authentication bypass, SQL or command injection, and memory overflows leading to remote takeover. HPE has seen neither a public exploit nor an attack so far.

**Why it matters**
Network equipment is ransomware's preferred way in, as seen this week with Palo Alto and Fortinet. Attackers often compare patched versions to build an exploit within days.

**Key takeaway**
Patch quickly, even without a known attack. In the meantime, the administration interface should only be reachable from a dedicated network (administration VLAN) or behind a firewall. Enable logging of administrator actions.

*Sources: BleepingComputer*

### BlackX: a Chinese bootkit gets past Secure Boot on fully patched PCs

**Espionage / State actors · Worth watching**

**What happened**
Kaspersky describes BlackX, a bootkit attributed with medium confidence to the Chinese group APT41. It targeted diplomatic agencies in Central Asia (Tajikistan, Uzbekistan, Turkmenistan), in a campaign discovered in early 2026. It exploits Baton Drop (CVE-2022-21894), an old flaw already used by BlackLotus, to start before Windows and disable protections. All the victims had the patches, but not the Secure Boot revocations, which have to be enabled by hand.

**Why it matters**
An installed patch is not always enough: some protections require an additional manual step. For Blue Teams, a bootkit is very hard to see, because it acts before the antivirus and the EDR.

**Key takeaway**
Always read the "additional actions" instructions in a security bulletin, not just the patch number. For Secure Boot, apply the revocations recommended by Microsoft (blocklist). An inventory of the Secure Boot state of the fleet is part of hardening.

*Sources: BleepingComputer*

### LiteLLM: GitHub tokens were stolen from logs

**Supply chain · Worth watching · Follow-up**

**What happened**
Reminder: a booby-trapped version of LiteLLM (1.107.0) was published on 21 October. The report updated on 23 October explains that the attacker found three developers' GitHub tokens in the logs of an internal LiteLLM server exposed to the internet. The attacker then used a lookalike repository, "Berri-AI/litellm" instead of "BerriAI/litellm", as the source of the booby-trapped code. The exact entry point remains unconfirmed; a recently fixed flaw is suspected.

**Why it matters**
Logs often contain secrets without anyone knowing. A forgotten internal server on the internet is enough to compromise an entire release chain.

**Key takeaway**
Mask tokens and passwords in logs, and limit token lifetimes. Check the exact spelling of a repository or package before using it: lookalikes are a classic trap.

*Sources: LiteLLM (incident report)*

## Glossary

- **Bootkit (UEFI)**: malware that launches when the computer starts, before Windows, which makes it very hard to detect and remove.
- **Secure Boot**: a boot protection that only allows programs signed by trusted publishers; it relies on lists of allowed and blocked signatures.
- **Web shell**: a small file dropped on a compromised web server that lets the attacker run commands on it from their browser.
- **Typosquatting**: a trap that uses a name almost identical to a real one (site, package, code repository) to fool hurried users.
