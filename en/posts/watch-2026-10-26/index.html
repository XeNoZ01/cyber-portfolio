PHP2Shell: the first real intrusions are confirmed

Published 2026-10-26 · 6 min read

PHP2Shell moves from attempts to successful intrusions; ChimeraZ claims 905,097 licence plate records, Microsoft 365 and GitHub token theft, the wider Brotli flaw and a trap for AI coding agents.

The essentials

  1. Five days after the fixes, PHP2Shell moves from attempts to successful intrusions: honeypots confirm code execution (a compromise of a European administration, announced then withdrawn, is corrected in the 27 October bulletin).
  2. In France, the hacker ChimeraZ adds 905,097 rows of licence plate data to their claims, while Renaissance and LFI deny any intrusion.
  3. On the defence side, two reports show that stealing a token (Microsoft 365, GitHub) is often worth more to attackers than a password.

PHP2Shell: first successful code executions confirmed

Vulnerability · Critical · Follow-up

What happened Reminder: two critical PHP flaws were fixed on 21 October. Until now, only failed attempts had been seen. Successful code executions, observed from 24 October and made public on 26 October, were recorded on decoy servers, notably by a Perplexity researcher (Apache with PHP 8.4.26), confirmed by Marcus Hutchins (Expel). Unit 42 (Palo Alto) had also reported that a European government entity was compromised (link to PHP2Shell later withdrawn, see the 27 October bulletin): within two hours, the attackers stole hashed passwords and MFA secrets, then targeted Active Directory.

Why it matters A flaw goes from “theoretical” to “dangerous” when a successful exploitation is proven: that threshold has just been crossed. In parallel, CYFIRMA attributes with medium confidence to a North Korea-linked actor a discreet scan of unpatched PHP servers. For a Blue Team, every PHP server that has not been updated must now be treated as potentially compromised.

Key takeaway Patching is no longer enough for a server that stayed exposed for several days: you must also look for traces of intrusion (suspicious processes, new accounts, connections to Active Directory). If updating is not possible right away, the setting session.upload_progress.enabled=0 is cited as a mitigation.

Sources: BleepingComputer · The Hacker News

ChimeraZ claims 905,000 licence plates, Renaissance denies

Data breach · Important · Follow-up

What happened The same hacker who is targeting political parties is selling 905,097 rows linking licence plates to their owners: names, addresses, emails and phone numbers, from 2017 to 2026. They say they took them from a “vulnerable site” that they do not name. Nothing indicates that the official vehicle registration file (SIV) was affected. For its part, Renaissance denies any intrusion and says the claimed data is public; LFI also speaks of scraping of public data.

Why it matters These claims are not confirmed, but a licence plate file can be used for very convincing scams (fake fines, fake impound notices). The case also shows a difficulty of GRC work: telling a real intrusion apart from a compilation of public data, which changes the notification obligations to the CNIL (the French data protection authority).

Key takeaway A hacker’s claim is not proof: we wait for confirmation from the victim or an independent analysis. For the general public, be wary of any message citing your licence plate and demanding a payment.

Sources: FrenchBreaches · Capital (via Yahoo Finance)

Microsoft 365: 97 accounts hijacked despite two-factor authentication

Attack · Important

What happened The vendor Huntress describes a campaign carried out from July to September 2026. The attackers stole Microsoft 365 sign-in tokens through fake login pages that relay the real one, then replayed them from their own machines. Result: 97 compromised accounts in 79 organisations. They then added their own authentication app and fake devices to keep access, and hid payroll-related emails.

Why it matters Classic MFA (code or notification) does not protect against this type of attack, because the attacker captures the already validated session. It is a typical scenario handled by a SOC analyst: sign-ins from an unusual IP, a new MFA method, a hidden mailbox rule.

Key takeaway After an account takeover, changing the password is not enough: you must revoke sessions and check MFA methods, registered devices and mailbox rules. Phishing-resistant security keys (FIDO2) block this type of attack.

Sources: The Hacker News

Gheist: stolen GitHub tokens used to drain the secrets of 850 accounts

Supply chain · Important

What happened Since September, Wiz has been tracking an automated campaign named Gheist. Using stolen GitHub tokens, it adds a branch containing a small workflow that prints all of the project’s secrets into the GitHub Actions logs, retrieves those logs and then deletes the run. More than 13,500 branches have been planted from more than 850 accounts, including private company repositories. The campaign was still active on 24 October.

Why it matters The stolen secrets (cloud keys, production passwords) open the door to the company’s systems. Some tokens come from past supply-chain attacks, such as the Trivy one in March: an old leak can be reused months later.

Key takeaway Look for branches named “ci-sync-” containing a file sync-check.yml. If you find any, change all secrets accessible to the repository: deleting the branch is not enough. Prefer short-lived, limited-permission tokens over permanent personal tokens.

Sources: The Hacker News

Brotli: the flaw also affects .NET, FFmpeg, ClickHouse and Apache Arrow

Patches · Worth watching · Follow-up

What happened Reminder: a flaw in the Brotli compression decoder was fixed on 21 October. JFrog researchers show that it also affects .NET, FFmpeg (via JPEG XL images), the ClickHouse database and Apache Arrow, with crashes or memory corruption. Microsoft began releasing .NET updates on 25 October; ClickHouse and Arrow do not yet have a fixed version.

Why it matters A single library can be embedded in dozens of programs, and each must be patched separately. Vulnerability scanners do not always see these hidden copies. No real-world exploitation is known.

Key takeaway Keeping an inventory of software components (SBOM) helps to know where a vulnerable library is hiding. Apply the .NET updates as soon as they arrive.

Sources: Cyber Security News

AI coding agents: a text file in Downloads is enough to trap them

AI and cyber · Worth watching

What happened Forever Security found, at a customer, a malicious AGENTS.md file placed in the Downloads folder. An AI coding agent launched in that folder read the file and tried to install a booby-trapped npm package. The researchers reproduced the attack on Codex (OpenAI) and, in a separate experiment, a CLAUDE.md file redirecting Claude Code (Anthropic) traffic to capture an authentication token. Why it matters AI agents obey the instruction files in their working folder: a simple text file can therefore trigger commands. This is a new type of risk to build into corporate AI usage policies.

Key takeaway Always launch an AI agent from the project folder, never from Downloads. Review any unknown instruction file and keep confirmation prompts enabled.

Sources: BleepingComputer

Glossary

  • Session token: a small piece of data handed over by a service after a successful login, which proves you are already authenticated. Whoever steals it can impersonate the user without a password or MFA.
  • Adversary-in-the-middle (AitM): a fake login page placed between the victim and the real site: it relays everything and captures the password, the MFA code and the session token along the way.
  • GitHub Actions: a GitHub service that automatically runs tasks (tests, deployments) on every code change. These tasks often have access to production secrets.
  • NTLM relay: a technique that captures a Windows authentication (NTLM protocol) and reuses it against another server to log in in the victim’s place, often to attack Active Directory.
