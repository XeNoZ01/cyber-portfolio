PHP2Shell : les premières vraies intrusions sont confirmées

Publié le 2026-10-26 · 7 min de lecture

PHP2Shell passe des tentatives aux intrusions réussies ; ChimeraZ revendique 905 097 plaques d'immatriculation, vol de jetons Microsoft 365 et GitHub, faille Brotli élargie et piège des agents de code IA.

L’essentiel

  1. Cinq jours après les correctifs, PHP2Shell passe des tentatives aux intrusions réussies : un pot de miel confirme une exécution de code et une administration européenne a été compromise.
  2. En France, le pirate ChimeraZ ajoute à ses revendications 905 097 lignes de plaques d’immatriculation, pendant que Renaissance et LFI contestent toute intrusion.
  3. Côté défense, deux rapports montrent que voler un jeton (Microsoft 365, GitHub) vaut souvent mieux qu’un mot de passe pour les attaquants.

PHP2Shell : première intrusion réussie confirmée, une administration européenne touchée

Faille · Critique · Suivi

Ce qui s’est passé Rappel : deux failles critiques de PHP ont été corrigées le 21 octobre. Jusqu’ici, on ne voyait que des tentatives ratées. Le 26 octobre, un chercheur de Perplexity a enregistré une vraie exécution de code sur un serveur piège (Apache avec PHP 8.4.26), confirmée par Marcus Hutchins (Expel). Unit 42 (Palo Alto) rapporte aussi qu’une entité gouvernementale européenne a été compromise : en deux heures, les attaquants ont volé des mots de passe chiffrés et des secrets MFA, puis visé l’Active Directory.

Pourquoi c’est important Une faille passe de « théorique » à « dangereuse » quand une exploitation réussie est prouvée : c’est ce seuil qui vient d’être franchi. En parallèle, CYFIRMA attribue avec une confiance moyenne à un acteur lié à la Corée du Nord un balayage discret de serveurs PHP non corrigés. Pour une équipe Blue Team, chaque serveur PHP non mis à jour doit maintenant être traité comme potentiellement compromis.

À retenir Corriger ne suffit plus pour un serveur resté exposé plusieurs jours : il faut aussi chercher des traces d’intrusion (processus suspects, nouveaux comptes, connexions vers l’Active Directory). La faille sœur CVE-2026-115560 n’a toujours pas de correctif : appliquer le réglage session.upload_progress.enabled=0.

Sources : BleepingComputer · The Hacker News

ChimeraZ revendique 905 000 plaques d’immatriculation, Renaissance dément

Fuite de données · Important · Suivi

Ce qui s’est passé Le même pirate qui vise les partis politiques met en vente 905 097 lignes reliant des plaques d’immatriculation à leurs propriétaires : noms, adresses, e-mails et téléphones, de 2017 à 2026. Il dit les avoir prises sur un « site vulnérable » qu’il ne nomme pas. Rien n’indique que le fichier officiel des immatriculations (SIV) ait été touché. De son côté, Renaissance dément toute intrusion et affirme que les données revendiquées sont publiques ; LFI parle aussi d’aspiration de données publiques.

Pourquoi c’est important Ces revendications ne sont pas confirmées, mais le fichier de plaques peut servir à des arnaques très crédibles (fausses amendes, faux avis de fourrière). Le cas montre aussi une difficulté du métier GRC : distinguer une vraie intrusion d’une compilation de données publiques, ce qui change les obligations de notification à la CNIL.

À retenir Une revendication de pirate n’est pas une preuve : on attend la confirmation de la victime ou une analyse indépendante. Côté grand public, se méfier de tout message citant sa plaque d’immatriculation et demandant un paiement.

Sources : FrenchBreaches · Capital (via Yahoo Finance)

Microsoft 365 : 97 comptes piratés malgré la double authentification

Attaque · Important

Ce qui s’est passé L’éditeur Huntress décrit une campagne menée de juillet à septembre 2026. Les attaquants ont volé des jetons de connexion Microsoft 365 via de fausses pages de connexion qui relaient la vraie, puis les ont rejoués depuis leurs machines. Résultat : 97 comptes compromis dans 79 organisations. Ils ont ensuite ajouté leur propre application d’authentification et de faux appareils pour garder l’accès, et caché les e-mails liés à la paie.

Pourquoi c’est important La MFA classique (code ou notification) ne protège pas contre ce type d’attaque, car le pirate récupère la session déjà validée. C’est un scénario typique traité par un analyste SOC : connexions depuis une IP inhabituelle, nouvelle méthode MFA, règle de boîte mail cachée.

À retenir Après un vol de compte, changer le mot de passe ne suffit pas : il faut révoquer les sessions, vérifier les méthodes MFA, les appareils enregistrés et les règles de boîte mail. Les clés de sécurité résistantes au phishing (FIDO2) bloquent ce type d’attaque.

Sources : The Hacker News

Gheist : des jetons GitHub volés pour vider les secrets de 850 comptes

Chaîne d’approvisionnement · Important

Ce qui s’est passé Wiz suit depuis septembre une campagne automatisée baptisée Gheist. Avec des jetons GitHub volés, elle ajoute une branche contenant un petit workflow qui affiche tous les secrets du projet dans les journaux GitHub Actions, récupère ces journaux puis efface l’exécution. Plus de 13 500 branches ont été plantées depuis plus de 850 comptes, y compris des dépôts privés d’entreprise. La campagne était encore active le 24 octobre.

Pourquoi c’est important Les secrets volés (clés cloud, mots de passe de production) ouvrent la porte aux systèmes de l’entreprise. Certains jetons proviennent d’attaques passées sur la chaîne d’approvisionnement, comme celle de Trivy en mars : une fuite ancienne peut resservir des mois plus tard.

À retenir Chercher les branches nommées « ci-sync- » contenant un fichier sync-check.yml. Si on en trouve, changer tous les secrets accessibles au dépôt : supprimer la branche ne suffit pas. Préférer des jetons courts et à droits limités aux jetons personnels permanents.

Sources : The Hacker News

Brotli : la faille touche aussi .NET, FFmpeg, ClickHouse et Apache Arrow

Correctifs · À surveiller · Suivi

Ce qui s’est passé Rappel : une faille du décodeur de compression Brotli a été corrigée le 21 octobre. Les chercheurs de JFrog montrent qu’elle touche aussi .NET, FFmpeg (via des images JPEG XL), la base de données ClickHouse et Apache Arrow, avec des plantages ou des corruptions mémoire. Microsoft a commencé à publier des mises à jour .NET le 25 octobre ; ClickHouse et Arrow n’ont pas encore de version corrigée.

Pourquoi c’est important Une seule bibliothèque peut être embarquée dans des dizaines de logiciels, et chacun doit être corrigé séparément. Les scanners de vulnérabilités ne voient pas toujours ces copies cachées. Aucune exploitation réelle n’est connue.

À retenir Tenir un inventaire des composants logiciels (SBOM) aide à savoir où se cache une bibliothèque vulnérable. Appliquer les mises à jour .NET dès qu’elles arrivent.

Sources : Cyber Security News

Agents de code IA : un fichier texte dans Téléchargements suffit à les piéger

IA et cyber · À surveiller

Ce qui s’est passé Forever Security a trouvé chez un client un fichier AGENTS.md malveillant posé dans le dossier Téléchargements. Un agent de code IA lancé dans ce dossier a lu le fichier et tenté d’installer un paquet npm piégé. Les chercheurs ont reproduit l’attaque sur Codex (OpenAI) et une variante sur Claude Code (Anthropic). Pourquoi c’est important Les agents IA obéissent aux fichiers d’instructions de leur dossier de travail : un simple texte peut donc déclencher des commandes. C’est un nouveau type de risque à intégrer dans les politiques d’usage de l’IA en entreprise.

À retenir Toujours lancer un agent IA depuis le dossier du projet, jamais depuis Téléchargements. Relire tout fichier d’instructions inconnu et garder les demandes de confirmation activées.

Sources : BleepingComputer

Mots du bulletin

  • Jeton de session (token) : petite donnée remise par un service après une connexion réussie, qui prouve qu’on est déjà authentifié. Qui le vole peut se faire passer pour l’utilisateur sans mot de passe ni MFA.
  • Adversary-in-the-middle (AitM) : fausse page de connexion placée entre la victime et le vrai site : elle relaie tout et récupère au passage le mot de passe, le code MFA et le jeton de session.
  • GitHub Actions : service de GitHub qui lance automatiquement des tâches (tests, déploiements) à chaque modification du code. Ces tâches ont souvent accès à des secrets de production.
  • Relais NTLM : technique qui capte une authentification Windows (protocole NTLM) et la réutilise vers un autre serveur pour s’y connecter à la place de la victime, souvent pour attaquer l’Active Directory.
